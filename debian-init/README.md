# debian-init

Интерактивный скрипт первоначальной настройки VPS на **Debian 12 (bookworm)** и **Debian 13 (trixie)**.

Без внешних зависимостей: чистый bash + текстовое меню, ничего ставить перед запуском не нужно.

## Быстрый старт

Выполнять **на сервере**, от root, сразу после создания VPS:

```bash
apt-get update && apt-get install -y git
git clone https://github.com/muodosta/server_utils.git
cd server_utils/debian-init
chmod +x init.sh
./init.sh --dry-run     # сначала репетиция: покажет, что будет сделано
./init.sh               # интерактивный запуск
```

## Как работает

1. Регистрируются модули из `modules/`.
2. Вы отмечаете нужные в текстовом меню.
3. **Все вопросы задаются сразу**, до внесения изменений — скрипт не остановится посреди установки пакетов и не будет ждать ввода через 10 минут.
4. Показывается сводка, вы подтверждаете словом `ДА`.
5. Модули применяются по порядку, после каждого — проверка результата.
6. Пишется отчёт `/root/server-init-report.txt`.

Каждый изменяемый файл сначала копируется в `/root/.server-init-backup-<дата>/` с сохранением пути, поэтому откат — это просто `cp -a`.

## Ключи запуска

| Ключ | Назначение |
|---|---|
| `--dry-run` | ничего не менять, только показать действия |
| `-y, --yes` | без вопросов, значения из профиля/по умолчанию |
| `--profile NAME` | загрузить `profiles/NAME.conf` (`minimal`, `docker`, `web`) |
| `--config FILE` | произвольный файл конфигурации |
| `--only "ssh firewall"` | выполнить только указанные модули |
| `--list` | список модулей |

## Модули

| id | Что делает |
|---|---|
| `base` | apt upgrade, базовые утилиты, hostname, TZ, локали, лимит journald, чистка exim4/rpcbind |
| `user` | не-root пользователь с sudo и SSH-ключом, `sudoers.d` с таймаутом |
| `firewall` | nftables **или** ufw, deny-by-default, SSH по whitelist IP |
| `ssh` | drop-in `99-hardening.conf`, смена порта, запрет пароля, современные шифры, **авто-откат** |
| `sysctl` | TCP BBR + fq, антиспуфинг, лимиты файлов, опционально отключение IPv6 |
| `swap` | swap-файл (на VPS его обычно нет, и OOM-killer убивает базу) |
| `updates` | unattended-upgrades **только** для security-репозитория |
| `f2b` | fail2ban или CrowdSec, banaction подбирается под выбранный файрвол |
| `docker` | Docker CE из официального репо, ротация логов, фильтрация через `DOCKER-USER` |
| `telegram` | PAM-хук: уведомление в Telegram при каждом входе по SSH |
| `backup` | restic или borg + systemd-таймер, шифрование, ротация |
| `motd` | сводка по серверу при входе |

## Три момента, на которые стоит обратить внимание

**1. Защита от самоблокировки.** Перед перезапуском sshd выполняется `sshd -t`, затем вооружается таймер systemd, который через N секунд вернёт исходный конфиг. Отменяется он только после того, как вы подтвердите успешный вход **в новом окне терминала**. В режиме `-y` таймер не вооружается — подтвердить некому.

**2. Debian 13 и socket-активация.** В trixie sshd запускается через `ssh.socket`, и директива `Port` в `sshd_config` игнорируется. Скрипт это определяет и дополнительно пишет `/etc/systemd/system/ssh.socket.d/99-port.conf`. Без этого смена порта «молча не срабатывает».

**3. Docker в обход файрвола.** `docker run -p 5432:5432` открывает порт всему интернету независимо от правил nftables/ufw, потому что трафик идёт через `FORWARD`/DNAT, а не `INPUT`. Модуль `docker` ставит правила в цепочку `DOCKER-USER`, которая обрабатывается до правил Docker, — это единственное штатное место для таких ограничений.

## Безопасность по умолчанию

- Политика `drop` на входящие, открыты только явно перечисленные порты.
- Никаких временных правил «на время настройки» — всё пишется в постоянный конфиг.
- Пароли и токены хранятся в `/etc/server-init/*.env` с правами `600` и **не** попадают в отчёт и лог.
- `nft -c -f` / `visudo -cf` / `sshd -t` — синтаксис проверяется до применения.

## Повторный запуск

Скрипт идемпотентен: повторный прогон не ломает уже настроенное. Отдельный модуль можно перезапустить через `--only`.

## Откат

```bash
# Полный лог
less /var/log/server-init.log

# Вернуть конкретный файл
cp -a /root/.server-init-backup-*/etc/ssh/sshd_config.d/99-hardening.conf /etc/ssh/sshd_config.d/
systemctl restart ssh
```
